01 · BLS retail meat prices and CPI¶

Milestone 1, items 1.1 and 1.2 · see docs/MILESTONES.md

What we're looking for¶

We need the monthly U.S. average retail price per pound for beef, pork and chicken from January 2015 to the latest month available, plus the Consumer Price Index (CPI) for the same months so we can adjust for inflation later.

BLS publishes several cuts of each meat. In this notebook we pull a few candidates for each meat, check which ones have complete data for our whole time range, and look at them side by side. Then we choose one series per meat and record why in docs/DECISIONS.md.

Steps

  1. Load the BLS API key from .env
  2. List the candidate series
  3. Download them from the BLS API
  4. Save the raw response, untouched, to data/raw/
  5. Turn it into a tidy table (one row per series per month)
  6. Check coverage: does each series have every month from 2015 to now?
  7. Chart the candidates for each meat
  8. Choose one series per meat

Step 2 · Candidate series¶

Every BLS average-price series has an ID. APU means average price, not seasonally adjusted; 0000 means U.S. city average (the whole country); the rest identifies the item.

Meat Series ID Item
Beef APU0000703112 Ground beef, 100% beef
Pork APU0000FD3101 All pork chops
Pork APU0000704211 Chops, center cut, bone-in
Pork APU0000704212 Chops, boneless
Chicken APU0000706111 Chicken, fresh, whole
Chicken APU0000FF1101 Chicken breast, boneless
CPI CUUR0000SA0 All items, U.S. city average, not seasonally adjusted

Why ground beef for beef? It's the beef cut most households buy, and it's the price quoted in most news coverage, so readers can compare our numbers with what they've seen. We'll still look at the chart before committing.

Why the not-seasonally-adjusted CPI? The meat prices aren't seasonally adjusted, so the CPI we divide by shouldn't be either. Mixing the two would add a seasonal pattern that isn't really there.

Step 3 · Download from the BLS API¶

We use version 2 of the BLS API, which needs the key. With a key, one request can fetch up to 50 series and 20 years, so all seven series come back in a single call.

The function stops with a clear message if BLS reports a problem, instead of quietly returning an empty table.

In [13]:
BLS_URL = "https://api.bls.gov/publicAPI/v2/timeseries/data/"

def fetch_bls(series_ids, start_year, end_year, api_key):
    """Request series from the BLS API v2 and return the parsed JSON response."""
    payload = {
        "seriesid": list(series_ids),
        "startyear": str(start_year),
        "endyear": str(end_year),
        "registrationkey": api_key,
    }
    resp = requests.post(BLS_URL, json=payload, timeout=60)
    resp.raise_for_status()
    data = resp.json()
    if data.get("status") != "REQUEST_SUCCEEDED":
        raise RuntimeError(f"BLS request failed: {data.get('status')} {data.get('message')}")
    return data

raw = fetch_bls(SERIES.keys(), START_YEAR, END_YEAR, BLS_API_KEY)

print("Status:", raw["status"])
for msg in raw.get("message", []):
    print("BLS message:", msg)
print("Series returned:", len(raw["Results"]["series"]))

Status: REQUEST_SUCCEEDED
Series returned: 7

How to read it¶

  • Status should be REQUEST_SUCCEEDED.
  • BLS messages are warnings. A common one is "No Data Available for Series X", which means that series doesn't exist or has no data in our years. That's useful: it rules the series out.
  • Series returned should be 7.

Step 5 · Tidy table¶

The API returns nested JSON: a list of series, each with a list of monthly values. We flatten it into a tidy table, one row per series per month, which is the shape pandas and charting tools work with best.

Details handled here:

  • Periods come as M01…M12. M13 is an annual average on some series; we drop it.
  • Values come as text. Missing months can appear as -, which we turn into a proper missing value (NaN) rather than an error.
  • BLS returns newest first, so we sort oldest first.
In [15]:
rows = []
for s in raw["Results"]["series"]:
    sid = s["seriesID"]
    for obs in s["data"]:
        if not obs["period"].startswith("M") or obs["period"] == "M13":
            continue
        rows.append({
            "series_id": sid,
            "date": pd.Timestamp(int(obs["year"]), int(obs["period"][1:]), 1),
            "value": obs["value"],
        })

prices = pd.DataFrame(rows)
prices["value"] = pd.to_numeric(prices["value"], errors="coerce")
prices["meat"] = prices["series_id"].map(lambda s: SERIES[s]["meat"])
prices["item"] = prices["series_id"].map(lambda s: SERIES[s]["item"])
prices = prices.sort_values(["series_id", "date"]).reset_index(drop=True)

Step 6 · Coverage check¶

What we're looking for: a series we can use needs every month from January 2015 to the latest month, with no gaps. A series that starts late or has holes would leave blank spots in the app's charts.

In [16]:
expected_months = pd.date_range(f"{START_YEAR}-01-01", prices["date"].max(), freq="MS")

coverage = (
    prices.dropna(subset=["value"])
    .groupby(["meat", "item", "series_id"])
    .agg(first=("date", "min"), last=("date", "max"), months=("value", "size"))
    .reset_index()

coverage["missing_months"] = len(expected_months) - coverage["months"]
coverage["first"] = coverage["first"].dt.strftime("%Y-%m")
coverage["last"] = coverage["last"].dt.strftime("%Y-%m")

missing_from_response = [s for s in SERIES if s not in set(prices["series_id"])]

  • months: how many months have a value.

The next cell lists exactly which months are missing, so we don't have to guess.

In [ ]:
missing = {}
for sid, g in prices.dropna(subset=["value"]).groupby("series_id"):
    have = set(g["date"])
    missing[sid] = [d.strftime("%Y-%m") for d in expected_months if d not in have]

pd.DataFrame({
    "item": [SERIES[s]["item"] for s in missing],
    "missing months": [", ".join(m) or "none" for m in missing.values()],
}, index=list(missing))

What it means¶

  • October 2025 is missing from every series, including the CPI. That's the month of the federal government shutdown, when BLS couldn't collect prices. It's a gap in the source data, not a problem with our download.
  • Whole chicken is also missing May 2020, early in the pandemic.
  • Bone-in pork chops stop after May 2026, so it's ruled out: the app needs a series that's still being published.
  • Every other series is complete apart from October 2025. That single month will be filled with the average of September and November 2025 during cleaning (decision D18), and flagged as filled.

What we're looking for: for each meat, do the candidate series tell the same story? If they rise and fall together, the choice between them matters less, and we can pick on other grounds, like which one shoppers recognize.

A first comparison with overall inflation¶

What we're looking for: how much each price changed from its 2015 average to the latest month, next to how much prices in general (the CPI) changed over the same period. This is a rough first look; Milestone 4 does it properly, month by month.

We compare against the 2015 average rather than January 2015 alone, so one unusual month doesn't skew the starting point.

In [ ]:
latest = prices.dropna(subset=["value"]).sort_values("date").groupby("series_id").tail(1)
avg_2015 = prices[prices["date"].dt.year == 2015].groupby("series_id")["value"].mean()

change = latest.set_index("series_id")[["meat", "item", "date", "value"]].copy()
change["avg_2015"] = avg_2015
change["change_since_2015_%"] = (change["value"] / change["avg_2015"] - 1) * 100
change["date"] = change["date"].dt.strftime("%Y-%m")
change = change.rename(columns={"date": "latest_month", "value": "latest_value"})
change.sort_values("change_since_2015_%", ascending=False).round(2)

How to read it¶

  • avg_2015: the average price (or CPI level) across 2015.
  • latest_value: the most recent month, September 2026 for most series.
  • change_since_2015_%: how much higher the latest value is than the 2015 average. The CPI row is the yardstick: anything above it rose faster than prices in general.

What it means¶

At the time of writing (data through September 2026):

Change since 2015 average
Overall prices (CPI) about +42%
Ground beef about +63% (faster than inflation)
Whole chicken about +39% (roughly in line with inflation)
Boneless chicken breast about +23% (slower than inflation)
All pork chops about +9% (far slower than inflation)

Beef is the only meat that clearly outran inflation. Measured against everything else people buy, pork and chicken breast actually got cheaper since 2015. That supports looking for beef-specific causes, like drought and the shrinking cattle herd (decision D17), rather than something that hit all meat equally.

The chart also shows that the chicken breast spike peaked in September 2022 (about $4.75/lb) and has partly come back down, while beef reached its highest point in **August 2026** (about $6.92/lb) and is still near the top.
